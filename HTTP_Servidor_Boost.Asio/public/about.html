Flujo de una solicitud

Una ruta.
Capas claras.

Cada clase posee una responsabilidad pequeña y verificable. Las sesiones comparten el router y conservan su propio socket, buffer, temporizador y strand.

TCP

Server → Session

async_accept entrega cada socket a una sesión administrada por shared_ptr.

HTTP

Parser → Router

Solo una solicitud completa y válida alcanza la resolución de rutas.

I/O

Response → Client

La respuesta serializada vive hasta completar async_write.

Client → TCP Socket → Boost.Asio → Session
       → HttpRequest → Router → HttpResponse → Client
Diseño orientado a objetos con separación .hpp / .cpp.
